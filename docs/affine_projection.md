# XOR を残せば、合成・内部変数の消去後も小さく保てる

**パリティの境界関係は、通常の CNF では指数個の節が必要でも、GF(2) の一次方程式なら一本で表せる。** この対照を、任意の有限 GF(2) 連立一次方程式に対する join と存在量化の実装で確認する。

これは既知の多項式時間で扱える制約クラスの再現であり、一般 SAT の解法ではない。[parity_projection.md](parity_projection.md) で確認した通常 CNF の下界を否定する結果でもない。出力に許す表現形式が異なる。

## API とデータの意味

実装は [src/pnp_lab/affine.py](../src/pnp_lab/affine.py)。外部依存はない。

```python
from pnp_lab.affine import AffineRelation

# (x XOR h = 0) AND (h XOR y = 1)
left = AffineRelation.from_named(("x", "h"), [(("x", "h"), 0)])
right = AffineRelation.from_named(("h", "y"), [(("h", "y"), 1)])
boundary = left.join(right).project(("x", "y"))
assert boundary.equations == ((3, 1),)  # x XOR y = 1
```

直接のコンストラクタは `AffineRelation(variables, equations)`。`variables` は順序を持つ、一意な文字列のタプル。方程式 `(mask, rhs)` の mask のビット i は `variables[i]` の係数を表し、rhs は整数 0 または 1 である。係数の足し算はすべて modulo 2。これは論理 OR の節ではない。

`from_named` は変数名を列挙した式も受け取る。同じ変数が二度現れたら GF(2) の規則で相殺する。未知の変数、範囲外のビット、重複したスコープ変数などはエラーになる。

| 操作 | 意味 |
|---|---|
| `join` / `conjoin` | 共有する変数名を同一視し、両方の制約を課す |
| `project(names)` | 指定した変数だけを、その順序で残す。他の変数は存在量化する |
| `exists(names)` | 指定変数を存在量化し、残りは元の順序で残す |
| `reorder(names)` | 変数集合を変えず、順序だけを変更する |
| `holds(named_bits)` | 名前付きの完全な割当を評価する。余分な名前は許す |
| `holds_mask(bits)` | 現在の変数順に沿った整数ビット列を評価する |
| `truth(scope)` / `false(scope)` | 恒真または恒偽の関係 |

生成時に行を正規化する。制約のない系は `equations=()`、矛盾した系は `((0,1),)`、つまり `0=1` で表す。空のスコープにもこの二つの関係がある。空スコープへ射影した結果は、元の系が可解なら真、不可解なら偽になる。

## なぜ射影できるか

境界を x、隠れ変数を z とすると、対象は

\[
R(x)=\exists z:\quad A_xx+A_zz=b
\]

である。実装は隠れ変数の列を先にピボットとしてガウス消去する。行の交換・他の行の加算はいずれも解集合を変えない。

消去後の各隠れピボット行は、そのピボット変数を、境界変数と自由な隠れ変数から一意に決める式になる。そのため、境界変数だけの行を満たす任意の割当は、自由な隠れ変数を選んでから隠れピボット変数を逆に求めれば拡張できる。

従って隠れ成分の残るピボット行を落とし、隠れ成分のない行だけを残せば、存在量化した境界関係を正確に表せる。`0=1` が生じた場合は、消去後も矛盾として保持する。

**元の式で隠れ変数を含む行を、そのまま削除する処理ではない。** たとえば `x=h` と `h=y` を合わせて h を消すと、`x=y` が残らなければならない。

共有する内部変数の扱いにも順序がある。二つの部品が同じ h を共有するなら、先に join してから h を消す。各部品から別々に h を消してから join すると、異なる存在証人を選べるようになり、別の関係になる。

## 計算資源

join は変数名を対応づけて方程式を合わせる。射影は有限行列の正確な消去であり、真理値表を作らない。矛盾しない正規化済みの系の独立な行数は変数数以下である。

この表現は dense な行列としても入力の変数数・方程式数に対して多項式サイズに収まる。ただし、途中の行は元の小さな XOR ゲートより密になることがある。幅 3 の形を保ったまま消去できると主張してはいない。

Python の整数は有限長の行を格納するビット集合として使う。長い整数の XOR、shift、popcount にはビット長に応じた費用がかかる。無限精度演算を一回の一定コストとして数えない。GF(2) のガウス消去は通常のビット計算でも多項式時間のアルゴリズムである。

## XOR 鎖による対照

構成は、`z2=x1 XOR x2`、`zi=z(i-1) XOR xi`、最後に `zn=0` とする。境界は `x1,...,xn`。元の系は `n` 本の一次方程式で、各方程式の変数数は最大 3。隠れ変数 `z2,...,zn` を消すと、

\[
x_1\oplus\cdots\oplus x_n=0
\]

という一本だけになる。

実験は `n=4,8,16,32,64,128,256` を扱う。大きな例でも、消去結果の係数が全境界変数で 1、右辺が 0、残る行が一本であることを正確に確認する。浮動小数点誤差や数値的な rank 判定は使わない。

`n <= 8` では全境界割当と、ゲートが強制する内部拡張を追加で確認する。`n <= 5` では全内部割当も独立に列挙する。既定の実験範囲ではこれは n=4 の128個の全割当に当たる。**n>8 の真理値表を全列挙したとはしない。**

| 境界変数 | 元の一次方程式 | 射影後の一次方程式 | 同じ関係を補助変数なし CNF で表す場合 |
|---:|---:|---:|---:|
| 4 | 4 | 1 | 8 節 |
| 8 | 8 | 1 | 128 節 |
| 16 | 16 | 1 | 32,768 節 |
| 32 | 32 | 1 | `2^31` 節 |
| 64 | 64 | 1 | `2^63` 節 |
| 128 | 128 | 1 | `2^127` 節 |
| 256 | 256 | 1 | `2^255` 節 |

CNF 側の個数は既知の下界から計算した値であり、大きな CNF を実際に生成した個数ではない。

## 独立な意味論テスト

[tests/test_affine.py](../tests/test_affine.py) は固定 seed で小さなランダムな系を作り、独立な有限全探索と比較する。

- 射影は120系。隠れ変数の全割当から存在証人を探して照合する。整合的な系と任意の右辺を持つ系の両方を含む。
- join は80組。共有変数の順序も変え、各入力の元の式を別評価して連言と照合する。
- 空スコープ、`0=1`、重複式、同じ変数の相殺、変数順の変更を検査する。
- 共有する h を join 前に消してしまうと異なる意味になる例も固定テストに含む。

## 位置づけと一次資料

GF(2) 一次方程式は、合成と射影の後も同じ形式で扱える既知の可解な制約クラスである。この例は、研究対象の形式を「境界だけの通常 CNF」から「XOR を保持する式」に変えると、前の障害を回避できることを示す。

一般の SAT の OR 節を、この形式へ小さく正確に変換できるという結果はない。任意の Boolean 関係が affine であるわけでもない。本実装の成功を一般 SAT へ拡大しない。

たとえば `x OR y` の真になる割当は 3 個である。一方、非空の GF(2) 連立一次方程式の解集合は affine 部分空間なので、その大きさは `2^d` になる。存在量化した結果もこの形式に閉じているため、線形な補助変数を増やすだけで、この 3 個の割当の関係を正確に表すことはできない。XOR に適した方法が、そのまま OR に広がるわけではない。

- Matthew Gwynne, Oliver Kullmann, [On SAT representations of XOR constraints](https://arxiv.org/abs/1309.3060)。GF(2) 系とその CNF 表現を区別するための背景資料。
- Gregory Emdin ほか, [CNF Encodings of Parity](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.MFCS.2022.47), MFCS 2022。補助変数なし CNF の `2^(n-1)` 節という既知の比較基準。

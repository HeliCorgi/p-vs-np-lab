# 3SAT を二変数 CNF と互いに独立な三変数 XOR へ移す

一般の 3CNF は、**各節が二リテラルの CNF と、互いに変数を共有しない三変数 XOR 行**の組合せへ、多項式時間で正確に変換できる。
ここでは初等的な一つの変換を実装し、各割当の意味と証人の対応を検証する。ガジェットや NP 完全性の新規性は主張しない。

この橋渡しは混合問題が一般の SAT を含むことを明示する一方、現在の商列挙ソルバーに高速化を与えない。
元の全変数が CNF に現れる標準形では、変換後の自由次元と観測 rank はともに **`n+2m`** となる。
この二点を同時に扱うのが実験の目的である。

## 1. 一節の正確な橋渡し

`a,b,c` を元の三リテラルの真偽値とする。新しい補助変数 `u,v,w` によって

\[
a\lor b\lor c
\quad\Longleftrightarrow\quad
\exists u,v,w:
(a\lor u)\land(b\lor v)\land(c\lor w)
\land(u\oplus v\oplus w=0)
\]

が成り立つ。

元の三リテラルがすべて偽なら、三つの二変数節が `u=v=w=1` を要求する。
そのパリティは奇数なので XOR 行と矛盾する。
少なくとも一つが真なら、その位置の補助変数だけを 0、残り二つを 1 にすればよい。
真のリテラルに対応する節はそのリテラルが満たし、他の二節は補助変数が満たす。補助変数のパリティも偶数になる。

この議論の `a,b,c` は変数名ではなくリテラルの評価結果である。
したがって符号付きリテラル、同じ変数の繰り返し、相補的なリテラルにもそのまま適用できる。
三つのリテラルの値が独立に選べるという仮定は必要ない。

## 2. 全式への合成、短い節、証人

各節には別々の三補助変数を用意する。元の変数の割当 `x` は全節で共有するが、補助変数は節の間で共有しない。
一節の同値を合成すると、すべての元の割当について

\[
F(x)\quad\Longleftrightarrow\quad\exists h\;G(x,h)
\]

となる。これは SAT / UNSAT を保存するだけでなく、補助変数を存在量化して元の関係に戻る同値である。

実装のリテラル `+i/-i` は元の明示的な変数表の `i-1` 番を参照する。
元の変数は変換後も同じ位置に残り、補助変数を後ろに追加する。
`auxiliary_triples` は各節の補助変数の **0 始まりの列番号**を保持する。

一リテラル節は `(a,a,a)`、二リテラル節は `(a,b,b)` として最後のリテラルを繰り返す。
これは OR の意味を変えない。空節は空節として残し、補助変数を作らない。
空の CNF は真であり、空スコープには一つの空割当がある。

`ThreeSatReduction.lift_witness(original_mask)` は、各節の最初の真の出現を選び、その補助変数を 0、他二つを 1 にする。
元の式を満たさない割当は拒否する。
`project_witness(full_mask)` は、変換後の割当を検査してから、元の変数に対応する低い `n` ビットを返す。
これらは明示的な有限の構成であり、効率の保証されない証人探索を変換手順に隠していない。

## 3. モデル数は保存しない

一節を三出現にパディングした後、その割当で真になる**出現数**を `s` とする。
偽の出現に対応する補助変数は 1 に固定され、真の出現の `s` 個だけが自由である。
一つのパリティ条件が残るため、補助変数の拡張数は

\[
e(s)=\begin{cases}
0,&s=0,\\
2^{s-1},&s>0.
\end{cases}
\]

ここで数えるのは異なる変数の数ではない。例えば単位節 `(a)` を `(a,a,a)` にした場合、`a=1` では `s=3` なので四つの拡張を持つ。

| 三出現の真の数 `s` | その真偽パターンの数 | 一割当あたりの補助変数の拡張数 |
|---:|---:|---:|
| 0 | 1 | 0 |
| 1 | 3 | 1 |
| 2 | 3 | 2 |
| 3 | 1 | 4 |

独立な三変数の節 `(a∨b∨c)` のモデル数は 7、変換後のモデル数は `3×1+3×2+1×4=13` となる。
全式では、元の満足割当 `x` の補助変数への拡張数は節ごとの積

\[
\prod_{j=1}^{m} 2^{s_j(x)-1}
\]

である。従ってこの変換は解の個数を保存する *parsimonious reduction* ではない。
変換後のモデルを一様に選んで元の変数に射影しても、一般に元のモデルの一様分布にはならない。
SAT の決定と証人の対応に必要な同値は保存している。

## 4. 大きさと、混合問題が一般の 3SAT を含む理由

元の式に `n` 変数と `m` 個の空でない節がある標準形では、出力は次の大きさになる。

| 対象 | 個数 |
|:---|---:|
| 元の変数 | `n` |
| 新しい補助変数 | `3m` |
| 全変数 | `n+3m` |
| 二リテラル節 | `3m` |
| 三変数 XOR 行 | `m` |

三変数 XOR 行はすべて右辺 0 で、補助変数の三組は互いに素である。
空節を許す API 全体では、上の `m` を空でない節の数とし、元の空節をそのまま加える。

これは変数・制約の個数についての線形増加である。
Python 実装の `AffineRelation` は長さ `n+3m` 程度の密なビットマスク行を保持するため、行の記憶量は `O(m(n+m))` ビットになりうる。
元の符号化の読み取り、変数名の衝突回避、ビットマスク生成、行の正規化も費用に含める。
必要な主張は**出力のビット長と構成の総ビット時間が多項式であること**であり、実装全体の厳密な線形時間は主張しない。

3SAT の NP 完全性を基準にすると [C]、上の明示的な多項式変換と満足可能性の同値により、この制限付きの二変数 CNF＋三変数 XOR 問題も NP 困難である。
一つの完全な割当を各二変数節と XOR 行で直接検査できるため NP にも属し、従って NP 完全となる。
一般の混合問題を速く解いたと主張する際に、XOR の存在だけで一般 SAT を対象外にできないことが分かる。

二変数 CNF 単独には多項式時間解法があり [APT]、XOR 単独には Gaussian elimination が使える。
さらにこの変換の空節のない出力では、**両部分は単独なら必ず充足可能**である。
すべての補助変数を 1 にすれば二変数 CNF を満たし、すべてを 0 にすれば XOR を満たす。
しかし前者は各三変数 XOR に違反する。二つの部分が同じ一つの割当を共有しなければならない点に、元の SAT の制約が残っている。

## 5. 現在の観測 rank は減らない

XOR 行の補助変数三組は互いに素なので、`m` 本の行は独立である。
元の変数は XOR 行に現れない。よって変換後の自由次元は

\[
d=(n+3m)-m=n+2m.
\]

補助変数の各三組には二つの独立な自由方向があり、三つすべての補助変数が二変数 CNF に現れる。
元の CNF に実際に現れる異なる元変数の数を `p` とすると、それらの係数形式も独立に観測される。
従って、この実装の観測 rank は

\[
r=p+2m.
\]

標準形で全元変数が現れるなら `p=n`、すなわち **`r=d=n+2m`** である。
各出力節は元変数と新しい補助変数の二つからなるため、現在の恒真節・重複の除去でもこの観測は消えない。
未使用の元変数がある場合だけ、それらに対応する `n-p` 方向が観測から除かれる。

現在の[商列挙法](mixed_solver.md)では、UNSAT の出力に対し決定モードでも `2^(n+2m)` 個のセルを調べる。
元の `2^n` 割当を直接列挙する方法に対し、この変換だけでは改善せず、むしろ `4^m` 倍の候補空間を作る。
他の混合ソルバーや、このガジェットを認識する前処理についての下界ではない。
この変換は一般問題を含むことの証明であり、高速化そのものではない。

### 四節の具体的な UNSAT 対照

元の式を

\[
(a\lor b\lor b)\land(a\lor\neg b\lor\neg b)
\land(\neg a\lor b\lor b)\land(\neg a\lor\neg b\lor\neg b)
\]

とする。二変数の四割当すべてを排除するため UNSAT である。
変換後は **14 変数、12 二変数節、4 XOR 行、`d=r=10`**。
`exhaustive=False` の決定モードで実際に **1,024 セル**を棄却した。元の全割当の検査は四つで足りる。
これは意図的に簡単な対照であり、難しい SAT インスタンスのベンチマークではない。

## 6. 実際に検証した範囲

局所ガジェットでは、三リテラルの真偽八通りと補助変数八通りの積、**64 割当**をすべて調べた。
生成された制約が定義の述語と一致すること、存在量化した意味、`s` ごとの拡張数を確認した。

全式では十例を扱い、元の割当を合計 **64 個**直接検査した。結果は SAT 七例、UNSAT 三例。
元の **39 個の満足割当すべて**を持ち上げ、変換後の原式で検査し、射影で元に戻ることを確認した。
ソルバーの SAT 証人も射影して元の直接 oracle と照合した。
全変数が九以下の変換先については、元変数への射影ごとの拡張数まで、合計 **1,346 個の完全な変換先割当**で独立に照合した。
この 1,346 は十例中の小さい変換先だけの合計であり、前述の局所 64 割当とは別の検査として数えている。

| 例 | 元の `(n,m)` | 変換後の `(全変数,d,r)` | 決定モードの検査数 | 元のモデル数 → 変換後のモデル数 |
|:---|:---:|:---:|---:|:---:|
| 正の三リテラル一節 | `(3,1)` | `(6,5,5)` | 8 | `7 → 13` |
| 符号付きで共有する二節 | `(3,2)` | `(9,7,7)` | 49 | `6 → 12` |
| 符号付き・繰り返し出現 | `(2,2)` | `(8,6,6)` | 28 | `2 → 5` |
| 単位節と二リテラル節のパディング | `(2,2)` | `(8,6,6)` | 20 | `1 → 8` |
| 四節 UNSAT 対照 | `(2,4)` | `(14,10,10)` | 1,024 | `0 → 0` |
| 四変数を共有する四節 | `(4,4)` | `(16,12,12)` | 405 | `8 → 54` |
| 未使用の元変数を一つ含む | `(4,1)` | `(7,6,5)` | 6 | `14 → 26` |

残る例は単位節の矛盾、空の式、空節である。
モデル総数を得るための全セル検査と、最初の SAT 証人で止まる決定モードの件数を JSON では別々に記録する。
決定モードだけで全セルを調べ終えた場合は、その結果をモデル数の検査にも再利用する。
trace と全セル証明書は出力しない。

## 7. Lean が確認する部分

`Formal/ThreeSatBridge.lean` は次の三定理を持つ。

- `clause_iff_gadget`：三つの Boolean 値についての局所同値。
- `clauses_iff_independent_helpers`：元のリテラル評価を共有し、各節には独立な補助変数を使う合成。
- `formula_sat_iff`：元の割当も存在量化した全式の満足可能性の同値。

三定理は Lean 4.19.0 による実ビルドと推移的な axiom audit を通過した。
確認した固定版は commit `613af6964e60ddf3872e3f36ae5e289f04caae5b` の
[GitHub Actions 実行](https://github.com/HeliCorgi/p-vs-np-lab/actions/runs/41698120371)である。

形式化の対象は Boolean 述語と存在量化の同値である。
Python 変換実装、符号化の処理、名前の衝突回避、多項式ビット費用、3SAT の NP 完全性そのもの、モデル数の式、現在の列挙法の実行時間までを形式化したという意味ではない。
それらの橋渡しは、実装・上記の数学的議論・有限の独立検証で別々に確認する。

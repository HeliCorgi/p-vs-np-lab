# One pass of checked resolution before split-parity refutation

The [wrapper](../src/pnp_lab/private_resolution.py) proves UNSAT for some signed 3-CNFs for which the one-pass [split-parity engine](../src/pnp_lab/split_parity.py) returns UNKNOWN. It uses ordinary propositional resolution, the classical elimination framework of Davis and Putnam, [*A Computing Procedure for Quantification Theory* (1960)](https://doi.org/10.1145/321033.321034). Neither resolution nor this private-variable identity is a new general SAT algorithm.

**Rule.** Count literal occurrences in the original raw rows. For a bit p occurring once positively and once negatively in two different clauses, resolve the original parents (p OR C) and (not p OR D) to (C OR D). A model with p false must satisfy C, and one with p true must satisfy D. Thus appending C OR D keeps *every original model*, with all original coordinates unchanged. A non-tautological resolvent of width at most three is retained if its literal set is not already present. We never remove either parent. Repeated raw occurrences disqualify the pivot rather than assuming it private.

The pass considers eligible pivots in ascending ID order and does not revisit newly added clauses as resolution parents. At most n clauses are added to m input rows. Clauses of width four, repeated clauses and tautological resolvents cost no further work. The underlying polynomial split-parity pass then uses the m+n bound. The checker can count occurrences by scanning the original formula for each proposed step; even that conservative check is polynomial in the explicit input size.

## Why a hidden parity becomes visible

Replace each clause (a OR b OR c) in a ternary parity encoding by the pair (a OR p), (NOT p OR b OR c), with a new p per clause. If a is true take p=false; otherwise satisfying the original clause requires b or c and p=true works. Conversely the pair entails the original clause by resolving once. The pass reconstructs every hidden clause, so an inconsistent set of original parity equations can once again be refuted by extracting rows and XORing them. No variable naming convention or Tseitin graph is an input to the wrapper.

In the [tetrahedron control](../tests/test_private_resolution.py), variables are the six edges of the complete graph on four vertices. Each vertex imposes one ternary parity equation with a prescribed charge. XORing the four equations counts every edge twice, so odd total charge is impossible. All 16 charge words are checked. On every padded instance (22 variables, 32 clauses) bare split-parity reports UNKNOWN. With the 16 privately resolved clauses, all eight odd charge words give checked UNSAT proofs. Every even case has a separately constructed raw 22-bit satisfying assignment and the refuter correctly abstains. This is not a claim that all Tseitin encodings are difficult for other preprocessors, or that arbitrary descriptions of a parity contradiction are found.

## Certificate boundaries

`private_parity_refute(n,clauses)` returns status UNSAT with a certificate, or UNKNOWN with none. The wrapper itself does not return SAT. The proof lists resolution records in increasing pivot order. For record j, the new row ID is m+j; both signed parent IDs must refer to **original rows**. The independent `check_private_parity(n,clauses,cert)` validates the premise counts, pivot signs, exact computed literal union, width, novelty and IDs, and replays the nested parity certificate on those exact rows. This checks the validity of each offered proof step; a different valid choice of unused derived clauses need not be rejected merely for being different. The tests cover malformed replacements, attempted derived parents, and a chain whose transitive resolvent is deliberately *not* produced.

There is no closure under repeated resolution here, and no mechanism for deciding all remaining SAT or UNSAT cases. A polynomial preprocessing pass per frontier member does not yield a polynomial bound on the number of frontier members.
